# copero Design System

## 产品上下文

copero 不是通用 SaaS 后台，也不是体育新闻站。源项目 `landing.html` 展示的是一个高保真响应式内容站首页：通过强情绪 Hero、职业结果卡、攻略内容流、多语言入口和高频 CTA，把用户从内容浏览迅速推进到官方试玩入口。

这套系统来自以下已复制证据：
- `landing.html`：完整首页原型与绝大多数组件、交互状态、版式与 token 来源
- `index.html`：源项目入口页，确认产品主表面是单一首页原型
- `critique.json`：对清晰度、层级、排版、动效、品牌的复盘要点
- `IMPLEMENTATION_PLAN.md`：证明项目是高保真、面向交付的产品化原型，而不是纯 moodboard

从证据可确认的产品能力与主表面：
- 响应式网页首页，而非多页面后台
- 足球题材人生模拟内容站，而非模拟器本体
- 真实主任务是“把用户送去试玩”
- 内容层围绕玩法解释、攻略入口、路线差异、分享传播与状态约束展开
- 多语言入口是结构要求，不是后加装饰

适用场景：
- 足球或体育题材的内容站首页
- 强 CTA 的游戏专题落地页
- 结果可分享的模拟游戏营销页
- 需要兼顾内容流、状态说明、语言入口与转化引导的响应式产品页

## 视觉基础

### 视觉姿态
源项目在 `landing.html` 中明确给出深色球场氛围、夜场霓虹点亮、强对比 Hero 和厚重结果卡。视觉张力主要来自排版重量、深浅层次和荧绿 / 金色的语义使用，而不是大量特效。

系统应保持：
- 深蓝黑背景作为第一层世界观
- 页面必须有绝对视觉重心，通常是 Hero 标题或职业结果卡
- 内容区按“吸引 → 解释 → 说服 → 引导行动”的顺序推进
- 情绪表达来自标题、对比和结果叙事，不靠多彩渐变乱轰

### 品牌姿态
从 `landing.html:554` 到 `landing.html:880` 可见，产品口吻始终围绕“几分钟踢完一生”“结果很能晒”“立即去官方免费玩”。因此品牌姿态应被锁死为：
- 主叙事是足球人生模拟的爽感与结果传播感
- 首页任务是转化，不是沉浸式百科全书
- 社区语感和街头足球感高于企业品牌感
- 设计要像内容站与玩家社区的交叉体，而非编辑部或企业官网

## 颜色系统

### 核心 Tokens
下列值直接来自 `landing.html:8-39`，不得擅自改成暖灰模板色：
- `--bg`: `oklch(14% 0.03 252)` 深蓝黑主背景
- `--surface`: `oklch(19% 0.026 248)` 卡片与导航表面
- `--fg`: `oklch(96% 0.01 110)` 主文字
- `--muted`: `oklch(74% 0.018 240)` 次级文字
- `--border`: `oklch(30% 0.024 246)` 边框与分隔
- `--accent`: `oklch(80% 0.22 145)` 主行动荧绿
- `--gold`: `oklch(82% 0.17 92)` 荣誉金强调

### 派生 Tokens
这些角色同样有源代码依据：
- `--accent-soft`: `color-mix(in oklch, var(--accent) 14%, transparent)`，用于按钮和高亮软底
- `--fg-soft`: `color-mix(in oklch, var(--fg) 6%, transparent)`，用于弱对比表层
- `--pitch-line`: `color-mix(in oklch, var(--fg) 14%, transparent)`，用于球场线条纹理
- `--shadow-soft`: `0 22px 60px color-mix(in oklch, var(--bg) 72%, black)`，用于厚卡片大软阴影
- `--focus-ring`: `color-mix(in oklch, var(--accent) 88%, white)`，来自源项目焦点样式

### 用色规则
证据显示颜色语义非常明确：
- 深蓝黑底色必须常驻，允许极弱径向绿光和金色点亮
- 荧绿只给主 CTA、焦点、选中态、积极状态和少量强调
- 金色只给传奇路线、奖杯、荣誉和高价值提示
- 禁止把背景改成暖米色、桃色、橙棕色或 generic AI wash
- 禁止多个高饱和 accent 同时争抢注意力

## 字体系统

### Display
来自 `landing.html:18` 与 `landing.html:102-104`：
- `--font-display`: `'Arial Black', 'Segoe UI', 'Helvetica Neue', system-ui, sans-serif`
- 用于 Hero、区块标题、球衣号码、结果卡大数字、品牌 lockup
- 规则：全大写、略负字距、粗壮、短句优先

### Body
来自 `landing.html:19`：
- `--font-body`: `-apple-system, BlinkMacSystemFont, 'Segoe UI', system-ui, sans-serif`
- 用于正文、说明、卡片文案、CTA 辅助文本
- 规则：保持多语言稳定性，避免花哨字体破坏响应式长度

### Mono
来自 `landing.html:20`：
- `--font-mono`: `ui-monospace, 'JetBrains Mono', 'SF Mono', Menlo, monospace`
- 用于年份、状态、语言缩写、阅读时长、编号与 tabular 数字
- 规则：承担结构信息，不做大面积段落正文

### 字号节奏
直接承接 `landing.html:21-26`：
- `--fs-h1`: `clamp(44px, 7vw, 92px)`
- `--fs-h2`: `clamp(30px, 4vw, 52px)`
- `--fs-h3`: `22px`
- `--fs-lead`: `19px`
- `--fs-body`: `16px`
- `--fs-meta`: `13px`

排版原则：
- 每屏一个主焦点标题
- 引导正文不超过约 `56ch`
- meta 信息统一使用 mono，避免正文风格污染

## 间距与形体

### 间距 Tokens
直接来自 `landing.html:27-36`：
- `--gap-xs`: `8px`
- `--gap-sm`: `12px`
- `--gap-md`: `20px`
- `--gap-lg`: `32px`
- `--gap-xl`: `56px`
- `--gap-2xl`: `96px`
- `--container`: `1180px`
- `--gutter`: `24px`
- `--radius`: `14px`
- `--radius-lg`: `24px`

### 版面节奏
从 `landing.html:80-100`、`landing.html:248-255` 和各 section 的实际结构可以抽出：
- 区块纵向节奏使用 48px–96px 的弹性区间
- 桌面端主表面是 split hero、多列卡片和 section stack
- `920px` 左右为大折叠点，多列统一退化为单列
- 不保留装饰性空栏；移动端优先保证信息顺序和 CTA 可达性

### 圆角与阴影
源项目圆角和阴影语义鲜明：
- 主卡片：24px 厚圆角
- 小徽章 / 图标格：12px–18px
- 按钮 / 语言切换：999px 胶囊
- 阴影大而软，但透明度克制，避免玻璃漂浮感

## 布局系统

### 页面结构
从 `landing.html` 可验证的默认结构：
1. Sticky 顶部导航
2. 双列 Hero（左文案，右职业结果卡）
3. 四步玩法区
4. 为什么会火 / 差异原因区
5. 攻略内容流
6. 多语言与分享墙区
7. 关键组件状态区
8. 设计规范区
9. 收尾 CTA 与页脚

### 网格模式
系统已有高信号网格类：
- `.grid-2`
- `.grid-3`
- `.grid-4`
- `.grid-2-1`
- `.grid-1-2`
- `.hero-split`
- `.content-grid`
- `.state-grid`
- `.spec-grid`

这些网格表达的不是抽象 utility，而是内容站真实布局习惯：标题一侧、内容一侧、卡片流一组、CTA 收尾一组。

### 响应式策略
- 首先保证移动端单列、按钮换行、语言入口换行
- 再扩展到桌面的双列 Hero 和多列内容流
- 多语言长度必须提前预留，不能靠缩字硬塞
- 移动端保留结果卡、CTA 和核心内容顺序，不为了“酷”而打乱阅读路径

## 组件系统

### 顶部导航
源于 `landing.html:117-168`：
- `topnav`：毛玻璃深色吸顶导航
- `logo-lockup`：徽章 + 粗 display 字标
- 主导航短词条，hover 仅加底边提示
- 右侧同时容纳语言切换和主 CTA

### 按钮
源于 `landing.html:170-202`：
- `btn-primary`：荧绿实心主按钮，hover 上浮并轻微旋转
- `btn-secondary`：深色描边按钮，hover 提边框与上浮
- `btn-ghost`：行内跳转按钮
- `btn-arrow`：通过箭头伪元素强化方向感

### 标签与 Pills
源于 `landing.html:227-246`：
- `pill`：金色语义信号，代表荣誉或栏目属性
- `tag`：普通描边胶囊，用于事实标签或主题点
- `language-pill`：带点状前缀的语言胶囊，强调语言入口存在感

### 职业结果卡
源于 `landing.html:256-355`，这是系统最关键的品牌组件：
- 核心子结构：路线徽章、球衣号码、评分格、姓名、描述、数据统计、职业时间线
- 作用：把抽象“模拟人生”能力具象化成可晒的个人结果
- 视觉特征：厚卡、透视微倾斜、局部金色高光、荧绿 / 金色共存但不混乱

### 内容卡与攻略流
源于 `landing.html:384-403` 与 `landing.html:698-734`：
- `content-card`：封面占位、pill、meta、标题、摘要、次 CTA
- 内容流不是博客列表，而是“最能带点击的攻略块”
- 内容卡 hover 只抬升、强调边框，不玩夸张浮层

### 原因卡 / 步骤卡
源于 `landing.html:214-225`、`landing.html:357-383`、`landing.html:621-645`：
- `intro-card`：四步玩法说明
- `reason-card`：为什么好玩的拆解卡
- `feature-mark` / `intro-step`：用于数字或小图形起点

### 状态组件
源于 `landing.html:431-462` 与 `landing.html:798-828`：
- `status-row`：一行一状态，左侧说明，右侧 pill
- `status-pill.empty`
- `status-pill.loading`
- `status-pill.error`

证据明确表明：空态、加载态、错误态属于系统本体，不是交付时可删掉的“说明卡”。

## 动效与交互

从 `landing.html` 和 `critique.json` 可确认：
- Hover 动效保持在 `0.14s`–`0.18s`
- 主按钮 hover 允许轻微上浮与极小角度旋转，表达街头足球感
- 卡片 hover 以抬升和边框强化为主
- `:focus-visible` 必须清晰可见，不能只照顾鼠标
- 背景网格与径向点亮只做气氛，不做持续重动画
- 语言切换、按钮、内容卡都必须支持真实交互状态，而不只是最终静态图

## 文案与品牌语气

证据来自 `landing.html` 文案与 `critique.json`：
- 语气直接、带判断、有点社区嘴劲
- 可以挑战错误思路，但不端着
- 强调“结果能晒”“几分钟一局”“免费开玩”这类立即收益
- CTA 永远导向真实行动：试玩、看攻略、继续比较
- 不写虚构官方数据，不冒充授权口吻

## 反模式

以下内容与源证据冲突，必须避免：
- 把页面做成企业 SaaS、数据后台或体育新闻站
- 用暖米色、桃色、橙棕色覆盖整个产品氛围
- 给每个标题都配图标，导致噪声过多
- 用多种高饱和色同时抢戏
- 把首页写成功能说明书或 FAQ 墙
- 发明不存在的评分体系、官方授权、玩家数量或社区热度
- 用假加载完成态和假外链糊弄交付
- 忽视多语言长度，把导航与按钮压坏
- 删除状态说明，只保留一张“最好看”的最终态海报

## 证据提炼总结

从现有源项目可以稳定提炼出的系统性结论：
- 目标单一：送去试玩
- 品牌组件单一：职业结果卡
- 内容重心偏攻略流与传播，而非资讯流
- 多语言入口和状态区是结构要求
- 响应式不是把桌面压扁，而是重排内容节奏

## 推荐复用方式

优先用这套系统去搭：
- 足球题材内容站首页
- 游戏专题落地页
- 路线对比页
- 攻略聚合页
- 玩家结果分享墙
- 多语言市场化营销页
